# Como contribuir com o NitRAM

Obrigado pelo interesse! Toda ajuda conta: ideias, testes, textos, traduções e relatos de problemas.

## Em que fase o projeto está

O NitRAM está em desenvolvimento e ainda não tem versão para baixar. Nesta fase, as contribuições mais úteis são:

- ideias de recursos e de melhorias;
- revisão da parte de privacidade (o que pode vazar da RAM e como evitar);
- quando sair a primeira versão, testes em diferentes versões do Windows.

## Abrindo uma issue

- **Problema ou erro:** use o modelo "Relatar um problema" e diga o que aconteceu, o que você esperava e como repetir.
- **Ideia:** use o modelo "Sugerir uma ideia" e explique o problema que ela resolve.
- **Falha de segurança:** não abra issue pública. Siga a [política de segurança](SECURITY.md).

Antes de abrir, procure se já existe uma issue parecida.

## Enviando um pull request

1. Faça um fork e crie um branch com um nome curto (`corrige-texto-privacidade`).
2. Faça commits pequenos, com mensagens claras em português.
3. Abra o pull request explicando o que mudou e por quê.
4. Para mudanças grandes, abra uma issue antes para conversar.

## Regra importante: só código original ou livre

O NitRAM é escrito do zero. **Não aceitamos**:

- código, trechos ou lógica copiados de programas proprietários, inclusive outros RAM disks comerciais;
- código obtido descompilando ou fazendo engenharia reversa de programas de terceiros;
- recursos visuais (ícones, telas, textos) de outros produtos.

Código de projetos livres é bem-vindo quando a licença for compatível com a GPL-3.0, com o crédito e o aviso de licença mantidos.

## Licença das contribuições

Ao enviar uma contribuição, você concorda que ela seja distribuída sob a mesma licença do projeto, a **GPL-3.0-or-later**.

## Conduta

Todos os participantes seguem o [código de conduta](CODE_OF_CONDUCT.md).
